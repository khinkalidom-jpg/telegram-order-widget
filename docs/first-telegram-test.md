# Первый тест BLOOM в Telegram

Код подготовлен, 23 теста проходят. Реальное подключение пока не проверено: в Codex нет токена, а доступ к Telegram ещё заблокирован действующей сетевой политикой. Превью — только имитация.

## Самый простой вариант: первый тест в Codex

Отдельный хостинг не нужен. Бот работает, пока работает облачная машина и запущен `npm start`. Это не постоянный сервер: после остановки/восстановления среды процесс нужно запускать заново.

1. **Создайте бота.** В Telegram найдите официальный **@BotFather**, нажмите **Start / Запустить**, отправьте `/newbot`. Введите название, затем свободное имя, заканчивающееся на `bot`. Скопируйте выданный токен. Если бот уже создан, используйте его существующий токен. Не отправляйте токен сюда в чат, в GitHub или на скриншотах.
2. **Откройте настройки среды Codex.** Выберите среду `telegram-order-widget` → настройки → переменные окружения (**Environment variables / Variables**; название раздела зависит от интерфейса). Поля уже добавлены в черновик. В `BOT_TOKEN` приватно вставьте токен целиком, без кавычек и пробелов. Это значение должно быть доступно процессу Node как настоящая переменная окружения; прокси-подстановка токена в HTTP-заголовки здесь не подходит, поскольку Bot API использует токен в пути запроса. Если интерфейс предлагает защиту/маскирование значения переменной, включите её.
3. **Остальные переменные.** `ADMIN_CHAT_ID` пока оставьте пустым: его узнаем ниже. `DATABASE_PATH` задайте `/workspace/telegram-order-widget/data/bloom.sqlite`. Без последнего значения бот использует `./data/bloom.sqlite` относительно папки запуска. Если интерфейс не позволяет сохранить необязательное пустое значение `ADMIN_CHAT_ID`, пока удалите это требование из настроек, затем добавьте с полученным ID.
4. **Разрешите сеть.** В настройках доступа к интернету (**Network / Internet access**) сохраните добавленные в черновик домены `api.telegram.org` и `core.telegram.org`, сохранив остальные разрешения. Первый нужен для работы бота, второй — для документации. Нажмите **Save / Сохранить**. Черновик сам по себе не меняет работающую машину; после сохранения требуется повторная проверка доступа. Для будущих задач опубликуйте конфигурацию среды через **Publish**, когда интерфейс это разрешит. Это публикация среды Codex, а не публичное развёртывание бота.
5. **Запустите процесс.** После сохранения настроек напишите в этом чате: «Настройки сохранены, запусти бота для теста». Секрет повторять не нужно. Если запускаете в терминале сами:

   ```sh
   cd /workspace/telegram-order-widget
   npm start
   ```

   Успешный запуск сообщает `BLOOM bot @имя_бота connected.`. Оставьте процесс работающим. Сообщение `.env not found. Continuing without it.` допустимо при настройке через окружение. Если сохраняли настройки при уже работающем боте, его нужно перезапустить. Одновременно должен работать только один экземпляр бота с этим токеном.
6. **Узнайте ID администратора.** Со своего аккаунта администратора откройте созданного бота по имени, которое выбрали в BotFather. Нажмите **Start / Запустить**, отправьте `/id`. Бот ответит `Chat ID: ...`. Скопируйте только число в `ADMIN_CHAT_ID` в тех же настройках Codex, сохраните и попросите перезапустить процесс. **Администратор обязан первым начать переписку с ботом.** Для демо можно быть и покупателем, и администратором с одного аккаунта.
7. **Откройте виджет.** В личном чате с ботом отправьте `/catalog`. Каталог должен появиться прямо внутри сообщения. Отдельный сайт, Web App, меню Mini App и публичный URL для этого не нужны. Используйте обновлённый клиент Telegram.
8. **Проверьте заказ.** Добавьте одну Red Roses и одну Pink Tulips: сумма должна быть **205 ₾**. Нажмите **Place demo order**. Должны появиться номер заказа и состав, а администратору — сообщение **DEMO** с той же суммой. Уйдите из чата и вернитесь: заказ должен сохраниться в виджете. Для нового заказа отправьте `/catalog`.

## Если что-то не работает

| Что видно | Что сделать |
| --- | --- |
| `Не задан BOT_TOKEN` | Заполните переменную в среде, примените настройки и перезапустите процесс. |
| `network-or-timeout` или запрет CONNECT 403 | Проверьте применение разрешения `api.telegram.org`; в текущем Codex это подтверждённый блокер. |
| Ошибка 401 | Проверьте токен из BotFather. При утечке замените его через BotFather. |
| Ошибка 409 | Остановите второй процесс с тем же токеном. |
| Сообщение о webhook | Для первого теста проще создать отдельного нового бота. У существующего сначала нужно согласованно отключить прежний webhook. |
| `/id` работает, но виджет не появляется | Обновите Telegram; пришлите только код ошибки и описание поведения, без токена. Возможность Widgets на реальном сервере ещё не подтверждена. |
| Нет уведомления администратора | Проверьте числовой `ADMIN_CHAT_ID`, начало переписки с ботом и перезапуск. Сохранённые уведомления будут повторяться автоматически. |

## Railway — только если нужен постоянный запуск

**Ниже инструкция на будущее. Развёртывание не выполнялось; переходить к нему следует после вашего подтверждения.** Railway может потребовать платный тариф: проверьте текущую стоимость до запуска.

1. Сначала загрузите подготовленный код в GitHub-репозиторий `khinkalidom-jpg/telegram-order-widget`. Сейчас файлы находятся только в рабочей папке Codex и ещё не закоммичены/не отправлены в GitHub. Не загружайте `.env`, `node_modules`, базы и логи. Загрузка кода в GitHub — отдельный шаг, здесь он не выполнялся.
2. В Railway войдите через GitHub, нажмите **New Project → Deploy from GitHub repo**, выберите `telegram-order-widget` и предоставьте доступ именно к этому репозиторию. Этот шаг может автоматически начать сборку/развёртывание — выполняйте его только после решения запускать Railway.
3. Откройте созданный сервис → **Variables** и добавьте:

   | Имя | Значение |
   | --- | --- |
   | `BOT_TOKEN` | Токен из BotFather, приватно, без кавычек |
   | `ADMIN_CHAT_ID` | Числовой ID из `/id` при тесте в Codex |
   | `DATABASE_PATH` | `/data/bloom.sqlite` |
   | `RAILPACK_NODE_VERSION` | `24.22.1` |

4. Прикрепите к сервису постоянный **Volume** с путём монтирования **`/data`** (в меню создания ресурсов проекта **New / Create → Volume**, названия могут отличаться). Без Volume заказы SQLite могут потеряться при пересоздании контейнера.
5. В **Settings → Deploy** задайте **Start Command: `npm start`**, **Replicas: 1**. Используйте стандартный Node/Railpack builder; отдельная команда сборки приложению не нужна. Отключите режим сна/Serverless, если он включён. Публичный домен, открытый порт и HTTP healthcheck не нужны: бот использует исходящий long polling, а `npm run preview` — другой, локальный процесс.
6. Перед запуском в Railway остановите бот в Codex. Примените настройки/выполните Deploy. В **Deployments → Logs** дождитесь `BLOOM bot @... connected.`. Повторите шаги 7–8 выше. На Railway будет новая пустая база: используйте `/catalog`, старые каталоги из Codex не привязаны к этой базе.

Версия Node через `RAILPACK_NODE_VERSION` проверена по [официальной документации Railpack](https://github.com/railwayapp/railpack/blob/main/docs/src/content/docs/languages/node.md). Названия кнопок Railway могут меняться; само развёртывание не проверялось.
